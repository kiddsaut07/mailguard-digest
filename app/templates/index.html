Local DMARC analysis

Understand an aggregate DMARC report

MailGuard Digest reads the aggregate reports produced by receiving mail servers and turns them into verifiable figures and a plain-language briefing. Nothing leaves this machine.

What it processes

A report is a single aggregate XML file describing one domain over one period. MailGuard Digest accepts the three formats you are likely to receive:

A .zip archive may contain several reports as well as directories. Ordinary files that are not DMARC reports are ignored and listed explicitly in the result.

How an analysis runs

  1. The file is validated, type and size checked before any content is read.
  2. Archives are opened in memory, with limits on entries, size and decompressed volume.
  3. Each XML report is parsed and validated against the DMARC structure.
  4. Deterministic rules compute totals, evaluated verdicts and dispositions.
  5. A briefing is written from those figures, and the results are stored locally.

Scope and limits of the tool

  • The analysis stays local: no upload, no email, no DNS change, no remote API, and no language model is involved.
  • Only the results are stored. The uploaded XML and archive contents are never written to the local database.
  • A DMARC pass is not proof that a domain or an address is safe, and an isolated failure is not proof that an address is malicious.
  • The tool never recommends switching a policy to quarantine or reject: published policy and observed dispositions are only described.
